# 相机光线的出水折射

本轮修改 WebGPU 相机渲染。WebGL2 兼容渲染仍保留旧实现。

## 原问题

连续水体和重建浪花在第一个入水界面执行 `refract(air/water)`，之后沿这条直线采样 72 次估算吸收厚度，直接查询地面/鸭子背景。采样到空气不会改变方向，因此悬空水层另一侧的出水界面、再次进入后方水层均未参与折射。

单独重建的解析椭球水滴已经计算了出水折射，但发生全反射时仍沿原方向透射；它之后的密度场也只参与厚度积分。

## 本地实现

- 沿同一个密度等值面寻找水/空气切换；六次二分细化交点，取局部法线，入水用 `1/1.333`，出水用 `1.333`。
- 相邻分离水层间继续追踪，吸收仅累计水中的路程，不把空气间隔计入厚度。原先的独立 72 次直线厚度采样已替换，未叠加一遍完整追踪。
- 出水及后续入水界面用非偏振 Fresnel 计算透射权重。全反射沿反射方向在内部继续追踪，避免错误透射。
- 最近的不透明接收面会截断当前线段，包括水中的鸭子，避免先穿过接收面再找出水口。
- 首个解析水滴保留精确椭球交点，之后继续追踪密度场；其全反射使用相同次数上限。
- 不改变粒子物理、数量、密度重建、渲染分辨率或焦散光线求解。无额外 GPU 缓冲、纹理和渲染通道。

物理依据：[PBRT 4e, Dielectric BSDF](https://pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF)。本实现仍是有限预算的实时透射近似，不是完整路径追踪：

- 第一次入水后最多处理 4 次界面事件/全反射，最多 256 次主步进；二分和法线采样另计。
- 水中步长 0.018，空气中 0.026，精度受密度网格和步进限制；更薄的层/空气缝仍可能漏掉。
- 不分裂追踪每个界面的非全反射反射分支；透射权重扣除了相应反射能量，但其后续反射贡献未完整求解。
- 预算耗尽且仍在水中时使用吸收后的环境近似，避免直接把背景当成已成功透射。高度重叠和长时间内部反射仍有误差。
- 后方独立解析水滴没有新的离屏加速结构；其参与情况取决于已有密度场。未实现任意多个解析水滴间的完整光线路径。

## 性能

2026-09-11，Apple M3 Pro，原生 Metal WebGPU，50,000 粒子，1250×800，反射、焦散、鸭子与水滴重建开启。与 `fd4eecaeb82dc71417079a835e1c5e24b541fd69` 对比，只切换主水面绘制管线。

同一物理预热状态下，每组恢复粒子、鸭子、浮力反馈和模拟时间，交替提交两个新/旧版本帧。80 帧去掉前 20 帧，各取 30 帧；GPU 时间戳统计，不含浏览器呈现/合成，不能直接作为浏览器 FPS。没有同时运行其他测试。

| 场景                 | 旧整帧 GPU 均值 | 新整帧 GPU 均值 |            增加 | 水体绘制阶段：旧 → 新 |
| -------------------- | --------------: | --------------: | --------------: | --------------------: |
| 平静，硬件浮点过滤   |        28.56 ms |        31.61 ms | 3.05 ms / 10.7% |        1.29 → 3.53 ms |
| 浪花，硬件浮点过滤   |        30.84 ms |        34.85 ms | 4.00 ms / 13.0% |        2.69 → 6.41 ms |
| 平静，手动三线性过滤 |        22.52 ms |        26.03 ms | 3.51 ms / 15.6% |        3.31 → 6.92 ms |

不同运行间 GPU 频率和调度存在变化，只应比较同一行交替运行的新旧差值；不能用第三行推断手动过滤比硬件过滤更快。第一轮硬件过滤实测整帧增加约 9.0% / 14.1%，与最终结果量级一致。原始最终样本摘要位于 `docs/experiments/refraction-results.json`。

成本主要随水体覆盖的像素数、穿越水体的路程、界面数量和采样能力变化，并非直接随粒子数成比例增加。分辨率更高、近距离观察和多层喷溅可能更贵；此处不是最坏情况上界。

## 验证与复现

`npm run test:webgpu:refraction` 直接运行生产 WGSL 追踪函数，与独立解析解对比平行水层、两层悬空水、楔形层、薄层、不透明遮挡、密度球体、解析水滴及全反射。测试隔离了界面求解，几何使用解析密度。

`npm run test:webgpu:caustics` 在生产三维纹理与完整着色器上检查实际厚度、出水 Fresnel、背景光照、地面及鸭子光照传输；另运行 `UNFILTERED=1` 覆盖手动过滤。`npm run test:webgpu:caustic-map` 验证原有光照投射。

配对性能脚本为 `docs/experiments/refraction-frame-benchmark.mjs`。先用 `git archive` 将基线提交的 `app/webgpu` 目录导出到临时目录，再将 `BASELINE_SHADER` 指向其中 `render-shaders.ts` 的绝对路径（需保留同目录导入）。默认测平静，`SCENE=rough` 测浪花，`UNFILTERED=1` 测手动过滤。两个版本在同一设备、同一模拟和重建资源上运行；基线着色器编译不计入测量。


## 后续本地修正：容器接触与自由界面分开

`ca54567` 的相机追踪把 `density()` 在 x=±1.86、z=±1.36、y=-.96 的硬裁切也识别成出水面。侧壁可能因此产生额外全反射；底部则把与 y=-.97 地板之间的 .01 建模间隙当成空气。上一版的均匀水层光照测试甚至把这次额外 Fresnel 当成预期，没有覆盖“湿接触”语义。

本地修正仅在交点精度范围（.0003）内识别这些裁切接触。贴底光线直接到最近接收面，吸收厚度补齐建模间隙；侧壁沿当前方向透过现有的装饰边界，不增加介质事件、Fresnel 或全反射。没有把靠墙的一整层水都屏蔽；离开裁切平面的真实密度表面继续正常折射。侧壁判断限定在可见容器高度 .8 以下，以上的悬空表面仍走正常出水路径。解析水滴也保留原光学路径。

这沿用项目中“侧壁仅为透明装饰、并非实体玻璃”的模型；不代表真实水—玻璃—空气系统没有反射。若以后添加有厚度的玻璃，应单独实现各介质及交点，而非套用此处的装饰边界处理。

验证：生产追踪函数覆盖四面侧壁/底部的大角度入射、离墙 .02 的自由表面、底部上方 .02 的自由表面、墙顶以上的悬空界面，以及原有薄层、水滴和内部全反射案例。生产密度纹理/完整着色器另覆盖四面墙与湿底接触，在硬件浮点过滤和手动三线性过滤下通过。未做浏览器视觉验收。

同一状态配对测试（50k / 1250×800 / M3 Pro，基线 `ca54567`），平静场景水体绘制由 3.45 ms 降到 1.97 ms，整帧 GPU 区间由 23.26 ms 降到 21.75 ms。与前面的历史绝对耗时不可跨运行直接对比；本组变化主要来自减少假界面的追踪，没有增加 GPU 通道或纹理。
