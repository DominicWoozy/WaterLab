# 压力与速度求解的精确邻居缓存

这次优化基于拟真优先的 3 × 4 求解版本。仍然每个 1/60 秒周期执行三个 1/180 秒物理子步，每子步四轮位置压力修正、两轮速度散度投影。没有减少粒子、改变张力与粘度、降低水面重建分辨率或关闭反射。只在本地修改。

## 瓶颈与选择

M3 Pro 原生 Metal、50,000 粒子的分阶段基准中，优化前物理约 23.0 ms，密度重建约 6.5 ms，渲染约 1.9 ms。阶段同步计时有额外开销，只用于定位；主要成本是物理中重复读取空间网格的候选粒子。

参考 [Neighbour lists for smoothed particle hydrodynamics on GPUs](https://www.sciencedirect.com/science/article/pii/S0010465517304198) 和 [Compressed Neighbor Lists for SPH](https://cg.informatik.uni-freiburg.de/publications/2019_CGF_CompressedNeighbors.pdf) 的邻居列表复用思路。本实现采用普通索引缓存，没有实现论文的压缩编码，也不跨时间步复用列表。

首轮曾尝试给位置压力阶段也建立带余量的列表；建表和大列表的访存抵消了收益，没有保留。首轮只缓存**位置已经固定**的粘度、张力及速度投影阶段。第二轮将缓存扩展到每轮压力修正，采用计算压力时顺便建表、仅供紧接着的修正复用的方式，不跨位置变化复用旧列表。

## 实现及精度边界

- 最后一次位置修正并重新分桶后，在一次 GPU 遍历内重建速度、计算压力系数和表面法线，同时记录半径内的精确邻居。
- 用支持球与网格单元的距离排除不可能相交的候选行，再用原来的粒子距离条件判定真正邻居。网格边界加小浮点余量，最终作用半径不变。
- 后续粘度、显式/可选隐式张力及散度投影复用索引，但继续计算原有的距离、核函数与力。
- 每个粒子最多缓存 96 个索引。实际邻居更多时记录完整数量，并回退到原来的完整网格遍历；**96 是缓存容量，不是物理邻居上限**。
- 每轮压力系数计算仍执行完整网格搜索，顺便重新记录邻居；紧接着的位置修正读取该列表。下一轮压力计算再次覆盖列表，不复用位置变化前的结果。速度阶段最后再重建一次自己的列表。
- 缓存放在现有 cell-starts 存储缓冲区的尾部，按邻居槽位连续排列，避免增加存储绑定。固定 50k 容量额外占用 19,400,000 字节，约 19.4 MB / 18.5 MiB。

保留原来的独立 velocity/factor 内核作为测试参考，生产调度使用合并内核。物理方程及求解预算一致，浮点累加及粒子排序仍可能使长期轨迹略有不同；不承诺逐位相同。

## 首轮性能（仅速度阶段缓存）

同一粒子和鸭子状态、相同模拟时长，交替执行优化版与优化前拟真版；1250 × 800，50k，张力、反射、焦散及原有水滴细节开启。丢弃前 20 帧，以 GPU 时间戳覆盖物理、水体重建和渲染：

| 静水场景 |   优化前 |   优化后 |
| -------- | -------: | -------: |
| GPU 平均 | 29.89 ms | 24.49 ms |
| GPU P50  | 29.03 ms | 23.79 ms |
| GPU P95  | 34.87 ms | 28.44 ms |

该次对照平均耗时减少约 **18.1%**，对应吞吐量增加约 **22.1%**。不能把吞吐量增幅当成浏览器实际帧率增幅；这些数字不包含浏览器显示合成。仍未恢复到更早的低精度五轮版本的耗时。

剧烈运动状态另作同状态交替对照：GPU 平均从 **28.48 ms 降到 23.73 ms**，减少约 **16.7%**；P95 从 29.36 ms 降到 24.25 ms，无 GPU 验证错误。扰动场景允许三个固定密度探针露出水面，基准只对它们检查非负有限值；静水场景仍要求三处均被水覆盖。

## 第二轮：增加缓存内容和复用范围的对照

用户允许使用更多显存，因此对三类方案作了独立的同状态交替对照。以下每行的基准均为首轮 96 索引缓存版本。设备负载会变化，只在同一行内计算相对收益，不把不同次实验的绝对时间相除。

| 方案 / 场景                      | 基准 GPU 平均 | 候选 GPU 平均 | 结果             |
| -------------------------------- | ------------: | ------------: | ---------------- |
| 容量 96 → 128 / 平静             |      23.64 ms |      23.79 ms | 无提速，未保留   |
| 额外缓存完整 f32 邻居梯度 / 平静 |      24.02 ms |      32.30 ms | 变慢，未保留     |
| 压力计算顺便记录索引 / 平静      |      27.02 ms |      23.23 ms | 减少 14.0%，保留 |
| 压力计算顺便记录索引 / 剧烈运动  |      25.15 ms |      22.11 ms | 减少 12.1%，保留 |

平静样本的实际邻居数平均 39.0，P95 为 47，最多 54；扰动样本平均 35.6，P95 为 46，最多 52。两者均没有超过 96。因此单纯扩大容量没有减少回退。它们只是采样场景，不是任意运动状态的邻居上限；极端密集输入仍使用完整搜索回退。

梯度版本把缓存扩大到约 77 MB，复用原有 f32 计算结果，没有压缩精度，但每个邻居增加三个浮点读写；实测额外访存成本超过节省的计算。将这类大梯度缓存也扩展到压力阶段同样变慢，均未写入最终实现。

最终方案复用同一块 19.4 MB 索引空间：每个子步有四轮压力计算，边计算边记录精确邻居，各供下一次修正使用，再由速度阶段覆盖。每个调度周期少做十二次完整网格候选搜索；建表工作合并在本来就要执行的压力遍历内。所有距离、梯度和压力继续使用原有 f32 计算，步长、四轮压力迭代、两轮散度投影和渲染设置均不变。

## 验证方法

`npm run test:webgpu:neighbors` 使用独立 CPU 全粒子对照，检查精确邻居集合、密度和粘度；还将合并后的速度、压力系数及表面法线与原独立内核对照。包含网格面附近粒子、孤立空邻居，以及 512 个粒子均超出缓存容量的密集情况，验证溢出回退不丢邻居。

第二轮新增压力系数与修正位移的独立全粒子对照。连续两次修正之间不重新分桶，并主动清空旧缓存计数，要求下一次压力遍历正确刷新邻居集合；同时覆盖小列表和 512 粒子溢出回退，检查修正没有改变粒子的其他属性。

完整静水、浮力、强扰动恢复及各粒子档位标准见 [静水求解记录](./static-water-stability.md)，运行 `npm run test:webgpu:settling`。另运行数值、张力、水体重建回归以及生产构建。没有浏览器视觉 QA。

首轮以上回归全部通过，另外五项画面呈现调度测试、修改文件 lint 和生产构建通过。首轮缓存版本的静水正压缩 RMS：50k 张力开 0.8433%，张力关 0.8453%，30k 0.5990%，15k 0.3828%；50k 鸭子平均支撑力 0.254915，对应模型重量 0.254800。强扰动数值场景的正压缩 RMS 为 1.266%，30 秒恢复测试为 0.8453%。

第二轮最终版本通过新增邻居/压力回归、完整静水回归、数值、张力、水滴重建测试、修改文件 lint 和生产构建。静水正压缩 RMS：50k 张力开 0.8429%，张力关 0.8466%，30k 0.5993%，15k 0.3825%；50k 鸭子平均支撑力 0.254910。强扰动数值场景正压缩 RMS 为 1.272%，30 秒恢复测试为 0.8441%。目标定义和适用范围保持原有标准。未修改呈现调度，未推送或发布。
