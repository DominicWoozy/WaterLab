# 相对邻居编号实验（2026-09-10）

基线为已发布的 `b99e3742494da3b870ae3ae0f31b654931e98bea`。目标是减少邻居访问成本，不要求显存分配一定变小。实验结束后已恢复全部运行代码，未推送或发布。

## 编码方案

每个粒子的邻居列表作为一个编码块，保存 32 位基址，两个 16 位偏移打包到一个 u32。仍有 96 个缓存邻居槽；实际邻居超过 96 个时保持原有完整网格搜索。编号跨度超出短偏移范围时整张表保存完整 u32 编号。这里区分两种溢出：邻居数量溢出走原有搜索，编号跨度溢出使用完整编号。

最终原型根据即将搜索的相邻网格单元的连续编号范围，提前选择短偏移或完整编号。两个建表内核搜索的单元均为该范围的子集。偏移范围包含 0～65535，可完整保存超过 65535 的全局编号，例如 66000～69999；没有降低位置、速度、压力的数值精度，也没有减少邻居或改变访问顺序。

保留原始宽格式的最坏情况空间以原地回退，五万粒子时额外分配一个基址平面，约 0.2 MB。因此本原型降低的是短格式列表的有效数据量和读写流量，不是分配显存。解码每个打包字后访问两个邻居，编解码不增加 GPU dispatch 或 CPU 回读。

## 性能结果

M3 Pro 原生 Metal，1250×800，完整物理、密度重建、水滴、鸭子、反射和焦散开启。相同粒子、鸭子、上一轮反作用力及模拟时间，每两帧交替原始／压缩版本；80 帧去掉前 20 帧，测第一物理 pass 到最终渲染结束的 GPU 区间，保持生产的分段提交方式。

| 版本与场景                           | 原始 u32 平均 | 压缩平均 | 结果                 |
| ------------------------------------ | ------------: | -------: | -------------------- |
| 首版动态检测跨度、原地扩展，50k 平静 |      25.69 ms | 27.31 ms | 慢约 6.3%            |
| 简化版提前确定宽度，50k 平静         |      18.26 ms | 18.25 ms | 约 0.08%，无有效收益 |
| 简化版提前确定宽度，50k 大浪         |      28.67 ms | 28.64 ms | 约 0.11%，无有效收益 |
| 简化版提前确定宽度，70k 平静         |      35.18 ms | 35.48 ms | 慢约 0.87%           |

不同轮的绝对时间受机器负载、热状态和模拟种子波动影响，只比较同行交替结果。不能把这些测量当成浏览器帧率。未单独测量硬件缓存命中率或解码指令耗时，因此“编解码抵消带宽收益”是解释结果的推断，不是硬件计数器证明。

70k 使用隔离源码副本：仅扩大缓冲容量并增加对应初始化排列，两组采用相同配置。它检验这次布局在更大计数下的表现，不代表网页已开放七万粒子，也没有完成正式七万档位的全套物理调参验证。

## 正确性

- 生产建表／遍历内核通过独立 CPU 全粒子邻居、压力和粘度对照。
- 513 粒子密集输入包含 512 个超过 96 邻居的列表，验证完整搜索回退。
- 独立 GPU 编解码往返验证编号大于 65535、偏移恰好 65535、偏移 65536 和 69999 的完整编号回退、0/1/2/3/95/96/97 长度，以及同一槽从宽格式重新变为短格式，不读旧数据。
- 所有成功实验均未出现 GPU 验证错误。没有浏览器视觉 QA。

保留的[实验补丁](./experiments/relative-neighbor-cache.patch)可应用到该基线后，执行原 `test:webgpu:neighbors` 及 [GPU 编解码边界测试](./experiments/relative-neighbor-codec.mjs)。补丁并未应用在最终工作目录，常规应用继续使用已发布的原始 u32 缓存。

本轮不保留压缩到运行路径：在当前设备与规模下，未实现用户要求的稳定性能提升。后续可独立评估按网格组织线程、共享邻居读取；本轮未实现该方案。
