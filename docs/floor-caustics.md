# 水面驱动的池底焦散原型

WebGPU 的池底光纹现在由当前水体密度场的实际表面折射生成；WebGL2 保留池底程序花纹近似。物理求解、粒子数量和水体重建参数不变。

## 接收位置

原着色器使用水面交点和法线生成正弦花纹，叠加到水的最终颜色，导致光纹像在水面发光。修复后只在 `room()` 实际命中 `y = -0.97` 池底时修改瓷砖照明。水面通过已有折射、吸收和 Fresnel 混合透射池底结果。视线先遇到鸭子、未命中池底或命中池边框时不叠加光纹。

池底上方 0.07 场景单位的密度用于湿润检测，干燥区域保持原有照明。

## WebGPU 光照流程

1. 在光照空间布置 192 × 144 条光线，使用场景现有太阳方向 `normalize(-0.6, 1, 0.35)`。
2. 对当前三维密度纹理步进求交并细化交点，复用水体渲染的等值面阈值、法线和鸭子 BVH。光线起点同时高于水面和鸭子，入水前及入水后都检查鸭子遮挡。
3. 按 Snell 定律、折射率 1.333 计算入水方向，与池底求交；根据 Fresnel 透射和水中路径长度计算 RGB 吸收。
4. 将相邻光线落点组成三角形，用入射网格面积与池底投影面积之比计算聚光强度，加法绘制到 512 × 384 的 `rgba16float` 照度纹理。
5. 池底材质采样此纹理，再经过已有视线方向的水体透射流程显示。

每次启用光纹的渲染帧重新生成照度图，无 CPU 回读。光纹不使用时间变量：只改变时钟、保持几何不动，照度图完全不变；实际水面起伏会改变聚光位置、强度和形状。平水面产生近乎均匀的照明，而非持续播放装饰花纹。

额外显存约 2.9 MB：光线数据 1,327,104 字节，照度纹理 1,572,864 字节。关闭光纹、关闭光照或启用粒子调试时跳过新增计算和投影阶段；空水池清除旧图。

## 性能验证

M3 Pro 原生 Metal、50,000 粒子、1250 × 800，同一粒子和鸭子状态交替执行原池底程序花纹与新焦散流程：

- 首次平静场景对照完整 GPU 区间：21.12 → 21.70 ms，增加约 0.58 ms / 2.8%。
- 后续单独时间戳探测新增“光线追踪 + 投影”阶段：平静场景平均 0.35 ms，大浪场景平均 0.21 ms，后者 P95 为 0.26 ms。此区间不包含最终池底纹理采样。
- 大浪完整帧对照受运行负载和异常值影响，新旧均值次序曾反转，不能据此宣称新流程加速。后续整帧耗时也高于首次测量；阶段测量仅用于判断新增工作的数量级。

这些是本机原生 GPU 测量，不包括浏览器合成，也不是跨设备帧率保证。没有进行浏览器视觉 QA。

## 正确性检查

`npm run test:webgpu:caustic-map` 使用生产焦散管线和可控三维密度场，验证：

- 平水面照明均匀，中央绿色通道均值约 0.854，标准差约 0.00012。
- 光线落点符合独立计算的 Snell 折射方向。
- 改变真实波面形状产生聚光和散光，改变波面相位使光纹位置变化。
- 仅修改时间不改变照度图。
- 真实鸭子网格遮挡光线，空密度场及零粒子重置清除旧图。

`npm run test:webgpu:caustics` 独立验证池底接收与透射合成：相同池底点不随观察方向改变其照度；鸭子遮挡、未命中池底、干池底无错误叠加；吸收和 Fresnel 权重符合独立计算；灯光和粒子调试开关有效。

以上两组测试在硬件线性和手动三线性采样路径都通过。水体细节重建测试、呈现稳定性测试（5 项）、TypeScript、修改文件 lint 和生产构建通过。此前 WebGL2 池底修复着色器也通过原生 OpenGL 编译链接检查。

## 近似边界

这是基于实际曲面折射的低成本焦散，并非完整路径追踪或体积散射：

- 只处理主体水池的单次空气到水界面，接收面为池底。陡峭表面、干池底、较长空气间隙会拒绝光线；不完整支持悬空水滴、多层薄片反复出入水、池壁焦散和多次反射。
- 法线和交点精度受现有密度场、光线步长和网格分辨率限制。投影三角形跨越明显表面断裂时丢弃，避免连接不同水团。
- 聚光面积比上限为 10，避免奇异折叠形成极亮闪点；叠加多个三角形后局部照度仍可高于 10。截断和丢弃意味着并非严格全局能量守恒。
- 太阳方向沿用现有固定光源，未新增太阳角度控制；没有使用时间动画伪造流动。
